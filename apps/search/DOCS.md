## Draft deterministic search — verified locally

B's pure modules live in `packages/shared/engine/{config,filters,home-fit,travel,score}.ts`. `filterListing(listing,intent,context?,hideUnconfirmed?,cheapOnly?)` mirrors cheap hard filters (active, nonduplicate, area, rent and home) and enriched fairness, opt-in safety and travel constraints. Areas are OR; destinations are AND. Unknown hard values pass with `not confirmed` notes unless hidden; unknown soft values are omitted. Room bedroom comparisons require explicit room accommodation; search-only studio matches a non-room, whole-unit listing with bedrooms zero. Pets `any` accepts any explicit pet permission, including cats-only or dogs-only; specific cats/dogs honor their corresponding restrictions. Hard inclusive bounds use exact matches; soft bedrooms/bathrooms score 100 inside, 50 up to one outside, zero farther away.

`scoreListing(listing,intent,{valuation,travel,safety,safetyScore?,caveats?})` returns all five parts and traceable metric evidence. The optional `safetyScore` is precomputed by D's owner function, not a replacement safety implementation or extension of D's authoritative export. Disabled safety contributes no score, caveats or weight. Null parts drop and weights renormalize; soft fairness defaults value to45, enabled safety to15. C supplies valuation and caveats unchanged. The engine contains no database, fetch, randomness or owner valuation/safety algorithms. All B tunables are in config; publishing them to A's `/data` methodology page remains pending.

Travel chooses the best normalized score among requested modes per destination. A confirmed passing mode wins; all requested modes must be confirmed failures to reject; otherwise the time requirement is unconfirmed. Straight-line distance is scored against walk800m/bike3000m/transit3000m/drive6000m, scaled by custom minutes relative to the category/mode default. It never becomes travel minutes.
