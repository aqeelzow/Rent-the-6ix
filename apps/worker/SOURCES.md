# SOURCES.md — listing sources: go / no-go

All adapters use [CloakBrowser](https://github.com/CloakHQ/cloakbrowser) (stealth Chromium, driven through Playwright; `src/lib/fetch.ts`): one page per source, `INGEST_REQUEST_DELAY_MS` between requests, `USER_AGENT`, retries on network errors and 5xx. Kijiji, Zillow and Realtor.ca also fetch each new or changed listing's own page for the full description and amenities (`INGEST_MAX_DETAILS` per run; contact fields never read). A 401/403/429 or a bot-check page (Cloudflare, captcha) stops the source for that run and marks it `unhealthy` (no retries, captcha solving or proxies on top of CloakBrowser).

Checked 2026-10-16 with `pnpm ingest:once --sources kijiji,torontorentals,rentals_ca,zillow,realtor_ca --pages 2` (plain Playwright); rentals_ca, zillow and realtor_ca rechecked with CloakBrowser, `--pages 1`.

**Where each source runs (2026-10-17):** the Vultr worker (`/srv/rentthe6ix`, Docker Compose `worker`, 6 h loop, full crawls) runs torontorentals, rentals_ca, zillow and realtor_ca: all four passed a one-page test from the server. **Kijiji returns HTTP 403 to the Vultr address**, so it stops there (no proxies or other workarounds) and runs from a team laptop instead: `pnpm --filter worker ingest:once --sources kijiji --pages 1000 --details 200`.

**Thumbnails (`imageUrl`, SPEC 8.5):** the team checked the four sites' terms on 2026-10-17 and they allow linking. The worker stores only the cover photo's https link and the card hot-links it (`referrerPolicy="no-referrer"`); images are never downloaded, stored or proxied, and the browser still blocks image loads while scraping. Fields: Kijiji `imageUrls[0]`, Zillow `imgSrc`, Realtor.ca `Property.Photo[0].MedResPath` (agent photos under `Individual` are never read). TorontoRentals / Rentals.ca (2026-10-17): the listing's `image` / `images[0]` `scales`, "medium" size (1348 × 900; same as "large"); 50/50 and 313/313 page-1 listings have one. The building contact block, its photo and promotion banners stay unread. Field names are from the site formats as known, confirmed live for Zillow and Realtor.ca on 2026-10-17 (Kijiji not yet, blocked from Vultr): if one is wrong, `imageUrl` just stays null and the card shows its placeholder.
